# simplify-swe-watcher

Checks the [SimplifyJobs Summer 2027 internship list and its off-season list](https://github.com/SimplifyJobs/Summer2027-Internships) every 2 minutes with GitHub Actions and sends a Telegram message through a bot for each new software engineering or data science, AI and machine learning listing, formatted as `<company> @ <time posted>, <date posted>` (for example `Atoms @ 2:14PM, November 27th`, in US Central time) with the yearly pay on a second line, so phone notification previews show the whole message. The company name links to the posting. Listings Simplify records with only a date show the date alone, and the year is added for dates outside the current year.

A listing counts when its category is `Software`, `Software Engineering`, `AI/ML/Data` or `Data Science, AI & Machine Learning`, its terms include `Summer 2027` or any Fall, Winter or Spring term, it is active and visible, and it is not graduate only. Graduate only uses the same rule as the graduation cap in Simplify's README: the listed degrees include a Master's, PhD or MBA but no Bachelor's or Associate's, or the title mentions a master's, MBA, PhD or doctorate. Before a new or reopened listing is sent, its pay is read from its Simplify job page and shown as a yearly USD range (hourly pay times 2,080 hours, with CAD, GBP and EUR converted at fixed approximate rates). A listing is skipped when the point 40% of the way up its pay range is under $80K a year, and listings with no pay listed are still sent, marked as such. IDs already notified are stored in `seen.json`, and listings that are currently closed are stored in `closed.json`. When closed listings open again, every reopening found in one check is sent together as a single summary message (newest 40 shown, with a count of the rest), even for listings sent before. The first run seeds both files without sending anything, and every new listing gets its own message, oldest first.

The bot token and chat ID come from the `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` repository secrets.

Each workflow run keeps checking for about 5 hours 40 minutes and then starts the next run itself, because GitHub often delays scheduled runs by hours. The 5 minute cron schedule is only a backstop in case that chain breaks. To stop the watcher, disable the workflow in the Actions tab.
